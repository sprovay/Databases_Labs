# Лабораторная работа №3 — аналитика и представления PostgreSQL

Предметная область — онлайн-кинотеатр из ЛР1–2. Изменения исходной схемы не требуются.

## Запуск

Выполнять из корня репозитория в **пустой базе PostgreSQL**:

```bash
createdb online_cinema_lab3
psql -X -v ON_ERROR_STOP=1 -d online_cinema_lab3 -f lab1/schema.sql
psql -X -v ON_ERROR_STOP=1 -d online_cinema_lab3 -f lab1/data.sql
psql -X -v ON_ERROR_STOP=1 -d online_cinema_lab3 -f lab1/migration.sql
psql -X -v ON_ERROR_STOP=1 -d online_cinema_lab3 -f lab2/data.sql
psql -X -v ON_ERROR_STOP=1 -d online_cinema_lab3 -f lab3/views.sql
psql -X -v ON_ERROR_STOP=1 -d online_cinema_lab3 -f lab3/materialized.sql
psql -X -v ON_ERROR_STOP=1 -d online_cinema_lab3 -f lab3/analytics.sql
```

`analytics.sql` содержит самостоятельные запросы и не зависит от представлений. После подготовки базы запустить демонстрацию отдельно:

```bash
psql -X -d online_cinema_lab3 -f lab3/demo.sql
```

`UPDATE` в пункте 2.3 файла `demo.sql` **должен завершиться ошибкой** из-за `WITH CHECK OPTION`. Поэтому для демонстрации не задан `ON_ERROR_STOP=1`: после ожидаемой ошибки выполняется пункт 3. Все временные изменения откатываются через `ROLLBACK`.

## Часть 1. Аналитические запросы

| Задание | Вопрос | Расчёт и контрольный случай |
| --- | --- | --- |
| 1.1 | Какие фильмы лидируют по завершённым просмотрам внутри каждого жанра? | `LEFT JOIN` сохраняет фильмы без просмотров; `COUNT ... FILTER` даёт им 0; `DENSE_RANK` присваивает равным показателям одно место. «Неоткрытый архив» присутствует с 0 просмотров. Фильм с несколькими жанрами входит в каждый свой жанр. |
| 1.2 | Сколько времени прошло с предыдущего просмотра пользователя? | `LAG` упорядочен по `(watched_at, watch_id)`, поэтому порядок однозначен даже при одинаковых отметках времени. У первого просмотра предыдущая запись и интервал равны `NULL`. |
| 1.3 | Сколько минут и какую долю от суммарного времени пользователя даёт каждый просмотр? | Оконная `SUM` добавляет итог к каждой операции, не сворачивая строки. Для пользователя с суммой 0 доля равна `NULL`, поскольку делить на 0 нельзя. Просмотр с нулевым прогрессом при положительной сумме даёт 0%. |

Контрольные данные ЛР2 содержат повторные просмотры, нулевой прогресс, фильмы без просмотров и одинаковые показатели. Запуск `analytics.sql` выводит все строки для проверки. `demo.sql` отдельно показывает, что «Неоткрытый архив» имеет 0 просмотров, а «Орбита» и «Сигнал» делят первое место в жанре «Фантастика». У `ivan_petrov` первый просмотр не имеет предыдущего; его просмотры составляют 169 и 75 минут из общего итога 244 минуты.

## Часть 2. Обычные представления

- `v_watch_operations` объединяет просмотры, пользователей, фильмы и необязательные рецензии. Изменение прогресса в исходной таблице сразу видно через представление.
- `v_genre_movie_ranking` сохраняет логику задания 1.1. Пример повторного использования выбирает первые три места жанра «Фантастика».
- `v_active_users` — простое обновляемое представление над `users`. `WITH CHECK OPTION` не даёт сделать пользователя неактивным через это представление.

В `demo.sql` есть фильтрация аналитического представления по жанру, изменение прогресса просмотра с 75 до 76 минут с немедленным отражением в `v_watch_operations`, успешное изменение имени через `v_active_users` и ожидаемый отказ при попытке изменить `is_active`.

## Части 3–4. Материализованное представление и актуальность

`mv_genre_monthly_stats` хранит число просмотров, уникальных зрителей, завершённых просмотров, просмотренных минут и долю завершённых просмотров для каждой пары «месяц × жанр». Месяц определяется в часовом поясе `Europe/Moscow`. Жанры без просмотров в имеющемся месяце выводятся с нулями. Один просмотр фильма с несколькими жанрами учитывается в каждом из них.

Такой отчёт может многократно читаться при планировании каталога; предварительный расчёт избавляет каждое чтение от соединения и группировки истории просмотров. Изменения исходных таблиц появляются в нём только после `REFRESH`. В `demo.sql` это проверяется изменением длительности просмотра: число минут в исходной таблице меняется сразу, в материализованном представлении — только после `REFRESH`. `ROLLBACK` возвращает исходное состояние.

Допустимая задержка для этого планового отчёта — **до 24 часов**. Политика: обновлять его ежедневно в 04:00 по московскому времени, после загрузки событий за предыдущий день. Автоматизация по заданию не требуется; команда для ручного или планового запуска:

```sql
REFRESH MATERIALIZED VIEW CONCURRENTLY mv_genre_monthly_stats;
```

Уникальный индекс по `(month_start, genre_id)` позволяет использовать `CONCURRENTLY`, чтобы чтение отчёта продолжалось во время обновления. Если обновление пропущено, отчёт следует считать устаревшим и выполнить команду вручную.
